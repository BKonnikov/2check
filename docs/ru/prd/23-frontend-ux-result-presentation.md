# 23. Пользовательский интерфейс и представление результатов

<!-- nav:start -->
[Концепция](../01-concept.md) · [Оглавление PRD](../02-prd.md) · [English](../../en/prd/23-frontend-ux-result-presentation.md)
<!-- nav:end -->

§23 определяет пользовательский сценарий, представление результата и функцию отправки изображения результата.

## 23.1. Основной сценарий

```text
Input
→ FULL/PARTIAL
→ RUNNING progress
→ FINAL Summary
→ Issues
→ DNS / Домен / SSL/TLS
→ Recommendations
→ Technical Details
```

## 23.2. Выполнение — RUNNING

Показываются состояния видимых категорий. Скрытые предварительные проверки не создают пользовательскую категорию DNS при сканировании только TLS.

Точный процент готовности не показывается, если сервер не предоставляет обоснованной оценки прогресса.

Предварительные Issue могут отображаться, но не как итоговое число проблем. Итоговая числовая оценка отсутствует во время RUNNING.

## 23.3. Порядок элементов итогового FULL

```text
Verdict
→ Score + Confidence
→ Issues
→ Category Cards
→ Technical Details
```

Вердикт является главным элементом. Клиент не выводит его из числовой оценки.

`score=100 + REDUCED` не представляется как безусловное «всё отлично».

## 23.4. Названия категорий

Основные названия в интерфейсе:

```text
DNS
Домен
SSL/TLS
```

Registry/RDAP/WHOIS используются как технические термины.

## 23.5. Неопределённость и неприменимость — UNKNOWN/N/A

UNKNOWN означает «не удалось проверить», а не подтверждённую проблему домена.

N/A нейтрален и может быть скрыт в сводке; технические подробности могут содержать фактическую причину.

## 23.6. Технические подробности

Получаются через `/details` по явному списку разрешённых полей, без административных или внутренних секретов.

## 23.7. Актуальность данных

`completedAt` не заменяет `checkedAt`.

Возраст кэшированных данных должен быть доступен. Разная актуальность результатов не сводится к вводящей в заблуждение общей временной отметке.

## 23.8. Обновление и повторная попытка

Обновление создаёт новое сканирование FORCE_REFRESH.

Действие повторной попытки основывается только на серверном `retryability`:

- RETRYABLE → немедленная повторная попытка допустима;
- CONDITIONAL → интерфейс учитывает условие или задержку;
- NOT_RETRYABLE → повторная попытка не предлагается как решение.

Клиент не сопоставляет reasonCode с поведением самостоятельно.

## 23.9. Отправка изображения результата

Для сканирования COMPLETED доступно действие:

```text
Поделиться
```

Модель отправки в MVP:

```text
existing ScanResult
→ on-demand Share Card image
→ native Share Sheet
```

Резервный вариант — сохранение изображения.

Отсутствуют:

- действие «Скопировать ссылку»;
- shareId/shareToken;
- отдельный URL или страница общего доступа;
- QR-код;
- серверная история отправок.

Карточка результата использует только безопасное публичное представление без технических подробностей, персональных данных, scanId, URL и originalInput.

Карточка FULL может показывать вердикт, оценку, уверенность, категории и проблемы. Карточка PARTIAL не показывает общей оценки или общего вердикта.

## 23.10. Доступность и адаптивность

Поддерживаются настольные и мобильные устройства. Обязательны управление с клавиатуры, видимый фокус, семантические заголовки и обозначения статусов помимо цвета. Технические таблицы могут прокручиваться горизонтально в пределах контейнера.

## 23.11. Критерии приёмки

- **AC-23.1** Сервер определяет вердикт, оценку, серьёзность, уверенность и возможность повторной попытки.
- **AC-23.2** Внутренние предварительные проверки скрыты из основного представления прогресса.
- **AC-23.3** PARTIAL не показывает общей оценки или общего вердикта.
- **AC-23.4** UNKNOWN не отображается как подтверждённая проблема.
- **AC-23.5** Кэширование и различия в актуальности отображаются достоверно.
- **AC-23.6** Повторная попытка использует переданное сервером retryability.
- **AC-23.7** Отправляется только изображение; сущность ссылки общего доступа отсутствует.
- **AC-23.8** Карточка не содержит персональных данных, scanId, URL, QR или внутренних данных.
- **AC-23.9** Поддерживаемые сценарии доступны с клавиатуры и используют обозначения помимо цвета.
