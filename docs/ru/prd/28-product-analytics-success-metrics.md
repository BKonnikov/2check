# 28. Продуктовая аналитика и показатели использования

<!-- nav:start -->
[Концепция](../01-concept.md) · [Оглавление PRD](../02-prd.md) · [English](../../en/prd/28-product-analytics-success-metrics.md)
<!-- nav:end -->

§28 определяет аналитику использования продукта. Эксплуатационная наблюдаемость остаётся предметом §21.

## 28.1. Разделение задач

Продуктовая аналитика показывает, как пользователи работают с продуктом.

Наблюдаемость показывает, как технически работает платформа.

Частота FAIL доменов не является KPI качества платформы.

## 28.2. Основные события

```text
scan_form_viewed
scan_submitted
scan_accepted
scan_result_viewed
technical_details_opened
refresh_clicked
retry_clicked
share_clicked
locale_changed
```

Необязательные события:

```text
share_completed
share_image_saved
```

Они используются, если API браузера позволяет достоверно определить исход действия.

## 28.3. Разрешённые измерения

Используются ограниченные наборы значений:

- locale: ru/uz/en;
- tool: home/dns/registry/tls;
- mode: FULL/PARTIAL;
- выбранный набор категорий как ограниченное перечисление;
- executionOutcome: COMPLETED/FAILED;
- необязательный агрегированный verdictCode.

## 28.4. Данные, запрещённые в аналитике по умолчанию

Не передаются:

- домен;
- scanId;
- originalInput;
- персональные данные регистрации;
- IP-адрес;
- отпечаток сертификата;
- значения DNS.

Страница сканирования учитывается как шаблон маршрута, а не фактический URL с scanId.

Сервис аналитики не является обязательной зависимостью выполнения; его отказ не влияет на сканирование.

## 28.5. Воронка использования

```text
scan_form_viewed
→ scan_submitted
→ scan_accepted
→ scan_result_viewed
```

Рекомендуемые основные показатели:

```text
completed_result_rate
FULL vs PARTIAL usage
technical_details_open_rate
share_action_rate
refresh_rate
returning_session_rate
```

Частота повторных попыток и обновлений интерпретируется совместно с наблюдаемостью, а не как самостоятельная оценка качества.

## 28.6. Конфиденциальность

Анонимный идентификатор сессии допустим для агрегированного анализа воронки и возвратов, но не является учётной записью или постоянным межсервисным идентификатором.

Введённый домен по умолчанию не используется как маркетинговый признак или характеристика аудитории.

Отправка изображения не создаёт аналитическую сущность получателя или просмотра.

## 28.7. Критерии приёмки

- **AC-28.1** Продуктовая аналитика и наблюдаемость разделены.
- **AC-28.2** Основная воронка сканирования измерима.
- **AC-28.3** Домен, scanId, originalInput и персональные данные отсутствуют в измерениях аналитики по умолчанию.
- **AC-28.4** Клиент не выводит событие повторной попытки из reasonCode.
- **AC-28.5** Аналитика отправки не отслеживает получателя или место назначения.
- **AC-28.6** Отказ аналитики не влияет на выполнение проверки здоровья домена.
- **AC-28.7** Анализ возвратов не требует истории домена.
- **AC-28.8** Клиентские эксперименты не меняют правила расчёта оценки, серьёзности или вердикта.
