# 17. Контракт внутреннего веб-API

<!-- nav:start -->
[Концепция](../01-concept.md) · [Оглавление PRD](../02-prd.md) · [English](../../en/prd/17-internal-web-api-contract.md)
<!-- nav:end -->

§17 определяет API между браузерной и серверной частями MVP. Публичный API фазы 3 в этот контракт не входит.

## 17.1. Конечные точки

```text
POST /api/web/v1/scans
GET  /api/web/v1/scans/{scanId}
GET  /api/web/v1/scans/{scanId}/details
GET  /api/web/v1/scans/{scanId}/registry/registrant
```

## 17.2. Создание сканирования — CreateScanRequest

```text
CreateScanRequest {
  input
  mode: FULL | PARTIAL
  selectedCategories?: (dns | registry | tls)[]
  cacheMode?: NORMAL | FORCE_REFRESH
}
```

По умолчанию `cacheMode=NORMAL`.

В FULL поле `selectedCategories` отсутствует. PARTIAL принимает непустое собственное подмножество `{dns, registry, tls}`. При выборе всех трёх категорий клиент обязан отправить `mode=FULL`. Если сервер получает `mode=PARTIAL` со всеми тремя категориями, запрос отклоняется как некорректный объём проверки: HTTP `422`. Неявное преобразование в FULL запрещено.

## 17.3. Подтверждение приёма — CreateScanResponse

```text
CreateScanResponse {
  scanId
  executionState: PENDING | RUNNING
  pollAfterMs?
}
```

`POST /scans` **подтверждает приём сканирования** и не является конечной точкой итогового результата.

Каноническая модель клиента:

```text
POST /scans
→ acceptance + scanId

GET /scans/{scanId}
→ authoritative current state
→ PENDING | RUNNING | COMPLETED | FAILED
```

Даже полное попадание в совместимый кэш не возвращает COMPLETED/FAILED в CreateScanResponse. Сканирование может завершиться между формированием ответа POST и первым GET; такое состязание по времени допустимо.

## 17.4. Ошибка веб-API — WebApiError

```text
WebApiError {
  errorCode
  message: MessageDescriptor
  field?
  retryable: boolean
  retryAfterSeconds?
  requestId?
}
```

Поле errorCode веб-API и `reasonCode` проверки принадлежат разным пространствам имён.

## 17.5. Ответ со сканированием — WebScanResponse

```text
WebScanResponse {
  scanId
  executionState
  mode
  canonicalDomain
  selectedCategories[]
  progress?
  categories[]
  summary?
  startedAt
  completedAt?
  pollAfterMs?
  failure?
}
```

Публичное представление CanonicalDomain не включает `originalInput`.

`categories[]` всегда соответствует `ScanPlan.visibleCategories`.

## 17.6. Возможность повторной попытки в представлении CheckResult

Представление для браузера поддерживает:

```text
retryability?: RETRYABLE | CONDITIONAL | NOT_RETRYABLE
retryAfterSeconds?
```

Значение определяется серверной политикой обработки сбоев из §18. Клиент не выводит возможность повторной попытки из `reasonCode`.

Результат по зависимости с `blockedBy` не получает искусственно назначенного собственного признака повторной попытки.

## 17.7. Значения HTTP-статусов

- 200 — чтение существующего сканирования независимо от вердикта здоровья домена;
- 202 — сканирование принято;
- 400 — некорректный формат или ошибка проверки ввода;
- 403 — отказ в контролируемом доступе;
- 404 — сканирование неизвестно или срок хранения истёк;
- 413 — слишком большой размер запроса;
- 415 — ошибка типа содержимого;
- 422 — недопустимый объём проверки;
- 429 — ограничение частоты запросов веб-API;
- 500 — сбой платформы на уровне запроса вне обычного жизненного цикла сканирования;
- 503 — невозможно безопасно принять сканирование.

Ответ провайдера 429 внутри сканирования даёт UNKNOWN проверки; GET сканирования сохраняет HTTP 200.

## 17.8. Обновление результата

Обновление создаёт новый `POST /scans` с FORCE_REFRESH. PATCH существующего сканирования отсутствует.

## 17.9. Ограничения безопасности

Клиент не может передавать произвольные IP-адреса, резолверы, провайдеров, порты, skipSSRF или сетевые параметры.

Неизвестные поля верхнего уровня запроса создания отклоняются; значения перечислений проверяются строго.

## 17.10. Критерии приёмки

- **AC-17.1** POST возвращает только состояния приёма PENDING/RUNNING.
- **AC-17.2** Авторитетное конечное состояние и результат доступны только через GET.
- **AC-17.3** Попадание в кэш не меняет модель POST→GET.
- **AC-17.4** HTTP-статус не кодирует здоровье домена.
- **AC-17.5** Видимые категории не включают внутренние предварительные проверки.
- **AC-17.6** Возможность повторной попытки определяется сервером и передаётся в представлении.
- **AC-17.7** Чувствительные данные регистрации с контролируемым доступом имеют отдельную конечную точку.
- **AC-17.8** Конечная точка для необработанных RDAP/WHOIS отсутствует.
- **AC-17.9** Обновление создаёт новый scanId.
- **AC-17.10** Пользователь не может переопределить сетевую политику или политику безопасности.
- **AC-17.11** `PARTIAL` с `dns+registry+tls` отклоняется с HTTP 422 и не преобразуется неявно в FULL.
