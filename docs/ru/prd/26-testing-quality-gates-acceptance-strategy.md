§26 определяет порядок проверки готовности выпуска.

## 26.1. Уровни тестирования

```text
Unit
```

## 26.2. Обязательные детерминированные проверки

- ввод, IDN и PSL;
- DNS: ANSWER/NODATA/NXDOMAIN, кворум, равенство голосов и различия значений;
- тестовые данные `.uz` RDAP/WHOIS: зарегистрированный и свободный домен, некорректный ответ, ограничение частоты и кодировки;
- TLS: действительный и просроченный сертификат, несовпадение имени, самоподписанная и недоверенная цепочки, просроченный промежуточный сертификат, IPv4/IPv6, протоколы и тайм-ауты;
- распространение зависимостей, включая `dependencyMode=ANY` для агрегированных TLS-проверок сертификата по одному и двум семействам адресов;
- инварианты reasonCode/blockedBy;
- SSRF: запрещённые диапазоны, rebinding и закрепление IP;
- устранение повторов Issue и запрет объединения между категориями;
- оценка, уверенность и вердикт;
- NORMAL/FORCE_REFRESH, single-flight и совместимость кэша;
- проверка политик и конфигурации;
- представления API и границы доступа;
- хранение и восстановление после сбоя.

## 26.3. Контрактные тесты повторной попытки

Серверные контрактные тесты охватывают RETRYABLE/CONDITIONAL/NOT_RETRYABLE.

Клиентский тест должен подтверждать отсутствие собственного сопоставления reasonCode. Контролируемые тестовые данные могут передавать известный reasonCode с намеренно изменённым retryability; клиент обязан следовать переданному retryability.

NOT_RETRYABLE не показывает немедленную повторную попытку; CONDITIONAL не превращается в безусловную немедленную попытку.

## 26.4. Тесты технического представления

Для TECHNICAL_INTERNAL обязательны:

- положительный случай: разрешённое поле присутствует в `/details`;
- отрицательный случай: неразрешённое поле того же класса хранения отсутствует.

## 26.5. Матрица совместимости браузеров

Обязательные браузеры:

1. Google Chrome для настольных систем;
2. Google Chrome для Android;
3. Apple Safari для macOS;
4. Apple Safari для iOS/iPadOS;
5. Microsoft Edge для настольных систем;
6. Mozilla Firefox для настольных систем;
7. Mozilla Firefox для Android;
8. Яндекс Браузер для настольных систем;
9. Яндекс Браузер для Android;
10. Samsung Internet для Android.

Для регулярно обновляемых браузеров проверяются текущий стабильный и предыдущий стабильный выпуск или поколение, доступные на практике.

Обязательны реальные движки Chromium, WebKit и Gecko.

Яндекс Браузер не считается автоматически покрытым тестами Chrome.

Opera для настольных систем — необязательная дополнительная цель.

## 26.6. Совместимость отправки изображения

При наличии нативного API отправки файлов используется системное меню отправки. В остальных случаях работает сохранение изображения. Отсутствие нативной отправки не делает браузер неподдерживаемым.

## 26.7. Внесение отказов

Минимальный набор сценариев:

- тайм-аут DNS;
- тайм-аут регистрации, некорректный ответ и ошибка кодировки;
- недоступность Redis;
- недоступность хранилища сканирований;
- тайм-аут TLS цели;
- внутренний сетевой сбой;
- ошибка проверки безопасности;
- общий срок завершения;
- авария рабочего процесса.

Потерянное RUNNING без безопасного возобновления получает FAILED `execution_state_unrecoverable`.

## 26.8. Блокирующие условия выпуска

Выпуск блокируется при:

- обходе SSRF-защиты;
- утечке персональных данных или секретов;
- неверной трактовке PASS/FAIL/UNKNOWN;
- повторном штрафе к оценке;
- повреждении исторического результата;
- неработающем сценарии FULL в обязательном браузере;
- отсутствии обязательного языка без безопасного резервного варианта.

## 26.9. Критерии приёмки

- **AC-26.1** Проверка критических инвариантов автоматизируется, где это возможно.
- **AC-26.2** Эталонные тестовые данные изолируют проверку корректности от нестабильности публичного интернета.
- **AC-26.3** Клиентское поведение повторной попытки проверяется по серверному представлению, а не таблице reasonCode.
- **AC-26.4** Техническое представление имеет положительные и отрицательные тесты разрешённых полей.
- **AC-26.5** Обязательная матрица браузеров проверяется до производственного выпуска.
- **AC-26.6** Регрессия SSRF или безопасности блокирует выпуск.
- **AC-26.7** Тесты карточки результата запрещают персональные данные, scanId, URL, QR и внутренние данные.
- **AC-26.8** Нагрузочные тесты проверяют корректность под нагрузкой, а не только пропускную способность.
- **AC-26.9** Тесты зависимостей покрывают `dependencyMode=ANY`: одно успешное семейство TLS разрешает оценку сертификата, оба успешных семейства участвуют в общем результате.
