# 18. Классификация ошибок и обработка сбоев

<!-- nav:start -->
[Концепция](../01-concept.md) · [Оглавление PRD](../02-prd.md) · [English](../../en/prd/18-error-taxonomy-failure-handling.md)
<!-- nav:end -->

§18 определяет уровни ошибок, причины, возможность повторной попытки и нормализацию сбоев.

## 18.1. Уровни ошибок

1. Ошибка ввода — до сканирования, без scanId.
2. Ошибка веб-API — на уровне запроса.
3. Техническая неопределённость проверки — UNKNOWN с reasonCode/blockedBy.
4. Сбой выполнения сканирования — FAILED, если достоверный итоговый результат невозможен.

Проблема цели даёт FAIL. Техническая невозможность проверки даёт UNKNOWN.

## 18.2. Правило reasonCode

`reasonCode` разрешён только для UNKNOWN с собственной технической причиной выполнения.

На PASS/FAIL/N/A поле `reasonCode` отсутствует.

UNKNOWN по зависимости использует только `blockedBy`.

## 18.3. Возможность повторной попытки

```text
RETRYABLE | CONDITIONAL | NOT_RETRYABLE
```

Соответствие кода возможности повторной попытки определяется серверной политикой обработки сбоев.

Примеры:

- provider_unavailable → обычно RETRYABLE;
- rate_limited → CONDITIONAL;
- provider_not_supported → NOT_RETRYABLE.

Клиент не хранит собственную параллельную таблицу соответствий.

## 18.4. Значение тайм-аутов

Тайм-аут не всегда означает UNKNOWN.

- тайм-аут DNS-провайдера может быть компенсирован при объединении по кворуму;
- исчерпанный тайм-аут провайдеров регистрации → UNKNOWN/timeout;
- тайм-аут TCP или рукопожатия проверенной цели → FAIL соединения TLS;
- внутренний сетевой сбой сканера после ALLOW → UNKNOWN/internal_network_error;
- незавершённая проверка безопасности до сетевой попытки → UNKNOWN/security_validation_incomplete;
- истечение общего срока сканирования → UNKNOWN/scan_deadline_exceeded.

## 18.5. Технические ошибки провайдера или источника

`malformed_response`, `parse_error`, `encoding_error`, `protocol_error` не означают отсутствия проверяемого объекта.

`module_execution_error` используется как общий резервный код только при отсутствии более точного.

Исходные строки исключений не используются как стабильный reasonCode.

## 18.6. Каталог сбоев сканирования

Используется канонический каталог §16 без дополнительных дубликатов.

## 18.7. Критерии приёмки

- **AC-18.1** Проблема цели и техническая невозможность проверки различаются как FAIL и UNKNOWN.
- **AC-18.2** reasonCode присутствует только у UNKNOWN с собственной причиной.
- **AC-18.3** blockedBy и reasonCode взаимно исключают друг друга.
- **AC-18.4** Возможность повторной попытки определяется сервером и конфигурацией.
- **AC-18.5** provider_not_supported имеет значение NOT_RETRYABLE.
- **AC-18.6** Классификация тайм-аутов зависит от этапа выполнения.
- **AC-18.7** Исходные исключения нормализуются в стабильные коды.
- **AC-18.8** Общий резервный код не используется при наличии точной причины.
