# 10. Проверка SSL/TLS

<!-- nav:start -->
[Концепция](../01-concept.md) · [Оглавление PRD](../02-prd.md) · [English](../../en/prd/10-ssl-tls.md)
<!-- nav:end -->

§10 определяет технические правила TLS-проверок.

## 10.1. Охват конечных точек

В MVP проверяется не более:

```text
1 representative IPv4
1 representative IPv6
```

`endpointCoverage = REPRESENTATIVE`.

Полное сканирование всех обслуживающих серверов не выполняется.

## 10.2. Выбор представительной точки

Выбираются только адреса, прошедшие проверку безопасности.

Порядок выбора:

1. наибольшее число наблюдений резолверами;
2. устойчивое детерминированное разрешение равенства.

## 10.3. Соединение

- TCP-соединение напрямую с выбранным закреплённым IP-адресом;
- порт 443/TCP;
- SNI = `asciiHostname`;
- отсутствие собственного неявного DNS-разрешения;
- HTTP-запросы и получение содержимого не выполняются.

Для TLS-полей `CheckResult.target/source` используются:

```text
TlsCheckTarget {
  kind: TLS_HOST
  hostname
  port: 443
  ipFamily?: IPV4 | IPV6
}

TlsCheckSource {
  kind: DIRECT_TLS_PROBE
  endpointCoverage: REPRESENTATIVE
}
```

`ipFamily` используется при проверках соединения для отдельного семейства адресов; в агрегированных проверках сертификата поле может отсутствовать. Выбранные IP-адреса и отпечаток зависимостей относятся к метаданным выполнения TLS (§19) и не дублируются в `TlsCheckSource`.

## 10.4. Поддержка протоколов

MVP проверяет TLS 1.2 и TLS 1.3. При наличии поддержки предпочтителен TLS 1.3.

## 10.5. Проверки сертификата

- срок действия;
- соответствие имени хоста;
- издатель;
- SAN;
- validFrom / validTo;
- число дней до окончания срока;
- проверка цепочки сертификатов;
- просроченный промежуточный сертификат;
- самоподписанный конечный сертификат;
- недоверенная цепочка.

В MVP не входят оценка наборов шифров, проверки устаревших атак, OCSP/CRL, HSTS, HTTP/2, QUIC, оценка CT и TLS1.0/1.1.

## 10.6. Соответствие имени хоста

Используется только SAN. Резервная проверка по CN отсутствует.

Подстановочный знак покрывает только одну полную крайнюю левую метку.

## 10.7. IPv4/IPv6

После общей проверки безопасности цели семейства адресов обрабатываются независимо.

Отсутствующее семейство получает N/A.

Агрегированные проверки сертификата используют `dependencyMode = ANY` между предварительными проверками соединения IPv4/IPv6. Для оценки сертификата достаточно одного успешного пути, по которому получен сертификат. Отсутствующее семейство, N/A, неуспех или UNKNOWN другого семейства не блокируют оценку доступного успешного пути; результат соединения другого семейства сохраняется отдельно.

Если сертификаты получены по обоим семействам, агрегированная оценка учитывает оба: недействительный сертификат любого проверенного семейства даёт FAIL соответствующей агрегированной проверки. Режим `ANY` определяет возможность запуска оценки, но не позволяет игнорировать второй доступный путь с сертификатом.

Если ни одно семейство не предоставило успешного пути с сертификатом, проверка сертификата не формирует самостоятельный отказ цели. Она получает конечный результат по зависимости через `blockedBy` согласно §7/§18.

Разные отпечатки сертификатов IPv4/IPv6 сами по себе не являются FAIL.

## 10.8. Классификация результатов соединения

После решения безопасности ALLOW:

- тайм-аут или отказ TCP-соединения с целью → FAIL соединения;
- тайм-аут или ошибка рукопожатия после фактической попытки обращения к цели → FAIL соединения;
- сбой сканера или сетевой инфраструктуры без достоверного наблюдения цели → UNKNOWN `internal_network_error`.

## 10.9. Коды технических причин TLS

Непосредственно применимые к модулю коды:

```text
internal_network_error
scanner_tls_error
```

Коды безопасности определяются в §15, коды оркестрации — в §16, общие правила — в §18.

## 10.10. Критерии приёмки

- **AC-10.1** На каждое семейство IP-адресов проверяется не более одной представительной конечной точки.
- **AC-10.2** TLS-клиент не выполняет повторное разрешение имени хоста.
- **AC-10.3** SNI использует asciiHostname.
- **AC-10.4** Имя хоста проверяется только по SAN, без резервной проверки CN.
- **AC-10.5** Отсутствующее семейство адресов получает N/A.
- **AC-10.6** Разные отпечатки действительных сертификатов между семействами не являются FAIL.
- **AC-10.7** Тайм-аут соединения с целью после ALLOW классифицируется как FAIL, а не UNKNOWN.
- **AC-10.8** Внутренний сетевой сбой сканера классифицируется как UNKNOWN/internal_network_error.
- **AC-10.9** Оценка шифров, HTTP, HSTS и OCSP не входят в MVP.
- **AC-10.10** TLS CheckResult использует контракт `TlsCheckTarget`/`TlsCheckSource` из §10.3.
- **AC-10.11** Агрегированные проверки сертификата используют `dependencyMode=ANY` между предварительными проверками соединения IPv4/IPv6: одного успешного пути с сертификатом достаточно для запуска, а все успешные пути с сертификатами участвуют в общей оценке.
