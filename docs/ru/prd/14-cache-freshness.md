# 14. Кэширование и актуальность данных

<!-- nav:start -->
[Концепция](../01-concept.md) · [Оглавление PRD](../02-prd.md) · [English](../../en/prd/14-cache-freshness.md)
<!-- nav:end -->

§14 определяет общий механизм внутреннего кэша и правила актуальности данных.

## 14.1. Назначение кэшей

Различаются:

1. внутренний кэш 2check для повторного использования результатов;
2. внешний кэш провайдера;
3. исторический или предыдущий ScanResult.

Redis обязателен.

## 14.2. Режимы кэша

```text
NORMAL
FORCE_REFRESH
```

NORMAL может использовать совместимый актуальный внутренний кэш.

FORCE_REFRESH:

- обходит внутренний кэш повторного использования для выбранного объёма проверки;
- выполняет новый внешний или сетевой запрос;
- записывает новый результат в кэш;
- не очищает кэш автоматически;
- не заставляет рекурсивный DNS-резолвер игнорировать собственный TTL.

## 14.3. Последовательное и одновременное обновление

Два последовательных FORCE_REFRESH, каждый после завершения предыдущего, создают два новых выполнения.

Одновременные FORCE_REFRESH могут объединяться только в уже выполняющееся получение свежего результата.

## 14.4. Устаревшие данные

Устаревший успешный результат не заменяет неудачное текущее обновление.

Текущий результат может иметь статус UNKNOWN; предыдущий или последний известный результат показывается отдельно.

## 14.5. Ключи кэша

Ключи модулей включают `cacheContractVersion` и относящиеся к ним версии технической конфигурации.

DNS:

```text
asciiHostname
resolverSetVersion
dnsModuleConfigVersion
cacheContractVersion
```

Регистрация домена:

```text
registryDomain
registryProvider
registryModuleConfigVersion
cacheContractVersion
```

Стабильный ключ TLS:

```text
asciiHostname
port
tlsModuleConfigVersion
trustStoreVersion
cacheContractVersion
```

Язык не входит в технический ключ кэша.

## 14.6. Совместимость зависимостей TLS

`dependencyFingerprint` не является частью стабильного ключа кэша.

```text
TlsCacheEntry {
  result
  dependencyFingerprint
  freshness
}
```

После поиска по стабильному ключу вычисляется текущий отпечаток DNS-зависимостей и условий безопасности. При совпадении повторное использование может быть разрешено; при несовпадении выполняется новая TLS-проверка.

## 14.7. Объединение одновременных запросов — single-flight

Одновременные одинаковые запросы NORMAL при отсутствии кэша могут объединяться.

Single-flight не объединяет `scanId`.

## 14.8. Кэш технических неудач

Временный UNKNOWN может кратковременно кэшироваться. FORCE_REFRESH обходит такой кэш.

## 14.9. Критерии приёмки

- **AC-14.1** Redis обязателен.
- **AC-14.2** FORCE_REFRESH не означает очистку кэша.
- **AC-14.3** Последовательные FORCE_REFRESH каждый раз создают новое выполнение.
- **AC-14.4** Устаревший успешный результат не скрывает текущий UNKNOWN.
- **AC-14.5** Язык не входит в технический ключ.
- **AC-14.6** Ключ регистрации использует канонический `registryModuleConfigVersion`.
- **AC-14.7** Отпечаток зависимостей TLS хранится как метаданные совместимости, а не стабильный ключ.
- **AC-14.8** Single-flight не объединяет идентификаторы сканирований.
