# 5. DKIM

<!-- nav:start -->
[Концепция](../01-concept.md) · [Оглавление PRD 1.1](../03-prd-1.1.md) · [English](../../en/prd-1.1/05-dkim.md)
<!-- nav:end -->

§5 определяет проверку DKIM: откуда берутся селекторы, что проверяется в найденном ключе и почему ненайденный ключ не считается его отсутствием.

## 5.1. Почему селектор нельзя узнать

Ключ DKIM публикуется по имени `<selector>._domainkey.<domain>`, где первая часть — селектор. Селектор выбирает владелец, и перечислить селекторы домена через DNS нельзя: имя можно только запросить, зная его заранее.

Это свойство протокола, а не пробел в проверке. Из него следует главное правило раздела: не найдя ключа, мы знаем, что не нашли его по тем именам, которые пробовали, — и ничего не знаем о том, есть ли ключ по другому имени.

## 5.2. Откуда берутся селекторы

Два источника, в порядке применения:

1. Селектор, введённый читателем. Необязательное поле рядом с доменом.
2. Селекторы почтового провайдера, распознанного по `MX` домена.

Второй источник работает потому, что провайдеры используют постоянные селекторы: домен с `MX` на почте провайдера почти наверняка публикует ключ по его селектору. Соответствие «провайдер — селекторы» задаётся версионируемой конфигурацией по правилам 1.0 §20 и не является частью кода.

Число имён, запрашиваемых за одну проверку, не превышает восьми. Это ограничение, а не перебор: проверка обращается к именам, которые имеет основание считать верными, и не подбирает их.

Если провайдер по `MX` не распознан и читатель не ввёл селектор, запрашивать нечего.

## 5.3. Признание записи

Запись читается из `TXT` имени селектора. Ответственный раздел для DNS-запросов — 1.0 §8.

Тег `v`, если он присутствует, должен иметь значение `DKIM1`. Ключ содержится в теге `p`.

## 5.4. Что проверяется в ключе

| Что найдено | Статус | Серьёзность |
|---|---|---|
| ключ пригоден | `PASS` | — |
| тег `p` пуст | `FAIL` | `critical` |
| ключ `rsa` короче `1024` бит | `FAIL` | `critical` |
| тег `h` допускает только `sha1` | `FAIL` | `critical` |
| тег `t` содержит `y` | `FAIL` | `warning` |

Пустой тег `p` — это отозванный ключ: запись есть, подписи по ней не проверяются.

Предел длины ключа взят из RFC 8301, который обновляет RFC 6376: проверяющая сторона не должна считать действительными подписи ключами короче `1024` бит. Оттуда же запрет на `sha1`: подписи с ним считаются заведомо непрошедшими.

Тег `t` со значением `y` объявляет режим испытания: получатель вправе не учитывать результат проверки подписи. Для домена, который считает DKIM настроенным, это тихая потеря защиты.

Ключи `ed25519` признаются наравне с `rsa` по RFC 8463; предел длины к ним не применяется.

## 5.5. Когда ключ не найден

| Что произошло | Статус | `reasonCode` |
|---|---|---|
| ни одно из имён не дало записи | `UNKNOWN` | `dkim_selector_unknown` |
| селектор введён читателем, записи по нему нет | `FAIL` | — |
| запрос не завершился | `UNKNOWN` | `dkim_lookup_failed` |

Разница между первой и второй строкой — это разница между «мы не знаем, где искать» и «мы искали там, где сказал владелец». Только во втором случае отсутствие записи — подтверждённый факт, и только он даёт `FAIL`.

`UNKNOWN` снижает уверенность в результате по правилам 1.0 §11. Сообщение проверки при этом прямо говорит, какие имена были опробованы, и предлагает ввести селектор.

## 5.6. Чего проверка не утверждает

- Что письма домена подписаны: публикация ключа и подписание писем — разные действия, и второе по DNS не проверяется.
- Что подпись на конкретном письме верна: без письма это не определено.
- Что у домена нет DKIM, если ключ не найден по опробованным именам.

## 5.7. Критерии приёмки

- **AC-5.1** Селекторы берутся из введённого читателем значения и из соответствия для провайдера, распознанного по `MX`; соответствие задаётся версионируемой конфигурацией.
- **AC-5.2** За одну проверку запрашивается не более восьми имён селекторов.
- **AC-5.3** Пустой тег `p` даёт `FAIL` с серьёзностью `critical`.
- **AC-5.4** Ключ `rsa` короче `1024` бит даёт `FAIL` с серьёзностью `critical`.
- **AC-5.5** Тег `h`, допускающий только `sha1`, даёт `FAIL` с серьёзностью `critical`.
- **AC-5.6** Тег `t` со значением `y` даёт `FAIL` с серьёзностью `warning`.
- **AC-5.7** Ключи `ed25519` признаются действительными; предел длины к ним не применяется.
- **AC-5.8** Отсутствие записи по опробованным именам даёт `UNKNOWN` с `reasonCode`, а не `FAIL`.
- **AC-5.9** Отсутствие записи по селектору, введённому читателем, даёт `FAIL`.
- **AC-5.10** Сообщение проверки называет опробованные имена и не утверждает, что у домена нет DKIM.
