# 13. Безопасность исходящих соединений

<!-- nav:start -->
[Концепция](../01-concept.md) · [Оглавление PRD 1.1](../03-prd-1.1.md) · [English](../../en/prd-1.1/13-outbound-security.md)
<!-- nav:end -->

[§13](13-outbound-security.md#13-безопасность-исходящих-соединений) определяет правила, по которым допускается соединение с почтовым узлом. Ответственный раздел для проверки адресов — [1.0 §15](../prd/15-security-ssrf.md#15-безопасность-и-защита-от-ssrf); его последовательность, классификация адресов и правило блокировки здесь не меняются, а распространяются на новый вид соединения.

## 13.1. Применение существующей защиты

MVP 1.0 уже устанавливает TLS-соединение с адресом проверяемого домена после проверки безопасности. Релиз 1.1 распространяет ту же последовательность на почтовые серверы, полученные по [§6](06-mx.md#6-mx).

Дополнительные ограничения определяют SMTP-порт, допустимые команды и число опрашиваемых серверов. Общие правила проверки адресов и закрепления выбранного IP сохраняются.

## 13.2. Последовательность

Порядок [1.0 §15](../prd/15-security-ssrf.md#15-безопасность-и-защита-от-ssrf) применяется без изъятий:

```text
MailHostTarget
→ DNS A/AAAA
→ full candidate set
→ Security Validation
→ ALLOW | BLOCK | INDETERMINATE
→ selected validated endpoint
→ pinned connection
```

Полный набор адресов узла проверяется без предварительного усечения. Если запрещён хотя бы один адрес, блокируется весь узел; исключить запрещённый адрес и соединиться с остальными нельзя — [1.0 §15](../prd/15-security-ssrf.md#15-безопасность-и-защита-от-ssrf).

Соединение идёт к закреплённому адресу. Имя узла не разрешается повторно библиотекой соединения.

## 13.3. Что ограничено жёстко

| Ограничение | Значение |
|---|---|
| порт | только `25` |
| источник имён узлов | только [§6](06-mx.md#6-mx) |
| команды сеанса | только приветствие, запрос расширений, переход на шифрование, завершение |
| число узлов за проверку | не более четырёх — [§7](07-starttls.md#7-starttls) |

Порт не принимается из пользовательского ввода или DNS-записей. Реализация не предоставляет возможности его переопределить.

Команды отправителя, получателя и передачи данных не выдаются никогда. Проба не отправляет писем и потому не может быть использована ни для рассылки, ни для проверки существования адресов.

## 13.4. Что это исключает

| Сценарий | Ограничивающая мера |
|---|---|
| заставить сервис соединиться с внутренним адресом | адрес узла проходит проверку [1.0 §15](../prd/15-security-ssrf.md#15-безопасность-и-защита-от-ssrf) наравне с любым другим |
| подменить адрес между проверкой и соединением | соединение идёт к закреплённому адресу |
| использовать сервис для сканирования портов | порт фиксирован |
| создавать избыточную исходящую нагрузку | число узлов ограничено; дополнительно действуют ограничения запросов и параллелизма из [1.0 §22](../prd/22-performance-resource-limits-nfr.md#22-производительность-и-ограничения-ресурсов) и [1.0 §25](../prd/25-privacy-data-protection-abuse-boundaries.md#25-конфиденциальность-доступ-и-защита-от-злоупотреблений) |
| отправить письмо чужими руками | команды передачи данных не выдаются |

## 13.5. Собственная инфраструктура

Запрет доступа к собственной инфраструктуре — [1.0 §15](../prd/15-security-ssrf.md#15-безопасность-и-защита-от-ssrf) — распространяется на почтовые узлы без изменений.

Блокировка по этой причине даёт `UNKNOWN` с объяснением ограничения сервиса и не уменьшает оценку домена.

## 13.6. Бюджет времени

Проба подчиняется общему бюджету сканирования [1.0 §22](../prd/22-performance-resource-limits-nfr.md#22-производительность-и-ограничения-ресурсов). Отдельного бюджета категория не вводит.

Из этого следует правило [§7](07-starttls.md#7-starttls): узлы сверх предела перечисляются как неопрошенные, а не ожидают освобождения времени. Результат, полученный частично, сообщается как частичный.

## 13.7. Критерии приёмки

- **AC-13.1** Адреса почтового узла проходят проверку безопасности [1.0 §15](../prd/15-security-ssrf.md#15-безопасность-и-защита-от-ssrf) в полном наборе, без усечения.
- **AC-13.2** Запрещённый адрес блокирует узел целиком.
- **AC-13.3** Соединение устанавливается к закреплённому адресу; повторное разрешение имени не допускается.
- **AC-13.4** Порт соединения равен `25` и не может быть задан вводом или записями домена.
- **AC-13.5** Имена узлов берутся только из результата [§6](06-mx.md#6-mx).
- **AC-13.6** В сеансе не выдаются команды отправителя, получателя и передачи данных.
- **AC-13.7** Блокировка по запрету собственной инфраструктуры даёт `UNKNOWN` и не уменьшает оценку домена.
- **AC-13.8** Категория не вводит собственного бюджета времени.
