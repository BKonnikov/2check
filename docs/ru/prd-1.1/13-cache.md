# 13. Кэш и свежесть

<!-- nav:start -->
[Концепция](../01-concept.md) · [Оглавление PRD 1.1](../03-prd-1.1.md) · [English](../../en/prd-1.1/13-cache.md)
<!-- nav:end -->

§13 определяет ключи кэша категории `email`, сроки жизни записей и то, что кэшировать нельзя. Ответственный раздел — 1.0 §14; режимы кэша, объединение одновременных запросов и правила устаревания здесь не меняются.

## 13.1. Ключи

Ключ строится отдельно для политик, для узлов и для списков блокировок.

```text
asciiHostname
policy
selector?
resolverSetVersion
emailModuleConfigVersion
cacheContractVersion
```

```text
mailHost
ipFamily?
emailModuleConfigVersion
cacheContractVersion
```

```text
address
blocklistSetVersion
emailModuleConfigVersion
cacheContractVersion
```

`selector` входит в ключ политик и обязателен для DKIM. Без него ответ по одному селектору переиспользовался бы для другого, и читатель получил бы чужой ключ как свой.

`blocklistSetVersion` меняется при изменении набора списков — §9. Смена набора обесценивает прежние ответы: «не числится» относится к тем спискам, которые спрашивали, а не к спискам вообще.

Язык в ключ не входит — 1.0 §14.

## 13.2. Сроки жизни

| Что кэшируется | Порядок срока |
|---|---|
| политики SPF, DMARC, DKIM | часы |
| записи `MX` и адреса узлов | часы |
| результат пробы шифрования | часы |
| ответ списка блокировок | минуты |

Точные значения задаются версионируемой конфигурацией по правилам 1.0 §20.

Срок для списков блокировок короткий намеренно. Попадание в список — состояние, которое владелец устраняет за минуты, и показывать вчерашнее попадание как сегодняшнее значит обвинять его в том, что он уже исправил.

Срок для пробы шифрования, наоборот, длинный: это единственная проверка категории, требующая соединения, а настройка шифрования на почтовом узле меняется редко.

## 13.3. Чего кэшировать нельзя

| Что | Почему |
|---|---|
| отказ списка обслуживать запрос | это не ответ, и сохранять его как ответ значит превращать в результат — §9 |
| неполный обход дерева DMARC | результат не получен, а не получен отрицательный результат |
| незавершённая проба шифрования | то же |
| селектор, введённый читателем | принадлежит запросу, а не домену |

Последняя строка существенна: введённый селектор не делает результат достоянием домена. Другой читатель, не назвавший селектора, должен получить `UNKNOWN`, а не готовый ответ, найденный по чужой подсказке.

Правила кэширования технических неудач в остальном — 1.0 §14.

## 13.4. Свежесть

`checkedAt` содержит время наблюдения, а не обращения к кэшу — 1.0 §6.

Для проверок, опрашивающих несколько источников, — узлы в §7, списки в §9 — временем наблюдения считается самое раннее из времён, вошедших в результат. Результат не свежее самой старой его части.

## 13.5. Критерии приёмки

- **AC-13.1** Ключ политики включает селектор; для DKIM селектор обязателен.
- **AC-13.2** Изменение набора списков блокировок меняет ключ и обесценивает прежние ответы.
- **AC-13.3** Отказ списка обслуживать запрос не сохраняется в кэш.
- **AC-13.4** Незавершённый обход и незавершённая проба не сохраняются в кэш как результат.
- **AC-13.5** Результат, найденный по введённому читателем селектору, не переиспользуется для запроса без селектора.
- **AC-13.6** Срок жизни ответа списка блокировок меньше срока жизни остальных записей категории.
- **AC-13.7** Время наблюдения составного результата равно самому раннему из времён его частей.
