# 12. Кэширование и актуальность данных

<!-- nav:start -->
[Концепция](../01-concept.md) · [Оглавление PRD 1.1](../03-prd-1.1.md) · [English](../../en/prd-1.1/12-cache.md)
<!-- nav:end -->

[§12](12-cache.md#12-кэширование-и-актуальность-данных) определяет ключи кэша категории `email`, сроки жизни записей и то, что кэшировать нельзя. Ответственный раздел — [1.0 §14](../prd/14-cache-freshness.md#14-кэширование-и-актуальность-данных); режимы кэша, объединение одновременных запросов и правила устаревания здесь не меняются.

## 12.1. Ключи

Ключ строится отдельно для политик и для узлов.

```text
asciiHostname
policy
selector?
resolverSetVersion
emailModuleConfigVersion
cacheContractVersion
```

```text
mailHost
ipFamily?
emailModuleConfigVersion
cacheContractVersion
```

`selector` входит в ключ политик и обязателен для DKIM. Без него ответ по одному селектору переиспользовался бы для другого, и пользователь получил бы чужой ключ как свой.

Язык в ключ не входит — [1.0 §14](../prd/14-cache-freshness.md#14-кэширование-и-актуальность-данных).

## 12.2. Сроки жизни

| Наблюдения | Порядок срока хранения |
|---|---|
| политики SPF, DMARC, DKIM | часы |
| записи `MX` и адреса узлов | часы |
| результат пробы шифрования | часы |

Точные значения задаются версионируемой конфигурацией по [1.0 §20](../prd/20-configuration-policy-management.md#20-управление-конфигурацией-и-политиками). Для пробы шифрования допускается больший срок, чем для политик, с учётом стоимости соединения.

Повторная проверка после изменения записей следует режимам кэша из [1.0 §14](../prd/14-cache-freshness.md#14-кэширование-и-актуальность-данных). Она не должна представлять прежнее наблюдение как новое.

## 12.3. Чего кэшировать нельзя

| Что | Почему |
|---|---|
| неполный обход дерева DMARC | результат не получен, а не получен отрицательный результат |
| незавершённая проба шифрования | то же |
| селектор, введённый пользователем | принадлежит запросу, а не домену |

Введённый селектор не добавляется автоматически в набор селекторов домена для других запросов. Запрос без селектора выполняет собственный поиск по [§5](05-dkim.md#5-dkim); результат прежнего запроса не может подменить его `UNKNOWN`.

Правила кэширования технических неудач в остальном — [1.0 §14](../prd/14-cache-freshness.md#14-кэширование-и-актуальность-данных).

## 12.4. Свежесть

`checkedAt` содержит время наблюдения, а не обращения к кэшу — [1.0 §6](../prd/06-common-data-contracts-exposure.md#6-общие-контракты-данных-и-уровни-доступа).

Для проверки, опрашивающей несколько узлов, — [§7](07-starttls.md#7-starttls) — временем наблюдения считается самое раннее из времён, вошедших в результат. Результат не свежее самой старой его части.

## 12.5. Критерии приёмки

- **AC-12.1** Ключ политики включает селектор; для DKIM селектор обязателен.
- **AC-12.2** Незавершённый обход и незавершённая проба не сохраняются в кэш как результат.
- **AC-12.3** Результат, найденный по введённому пользователем селектору, не переиспользуется для запроса без селектора.
- **AC-12.4** Время наблюдения составного результата равно самому раннему из времён его частей.
