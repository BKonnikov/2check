# 6. MX

<!-- nav:start -->
[Концепция](../01-concept.md) · [Оглавление PRD 1.1](../03-prd-1.1.md) · [English](../../en/prd-1.1/06-mx.md)
<!-- nav:end -->

[§6](06-mx.md#6-mx) определяет проверку записей `MX`: как находится принимающий сервер, что считается исправной настройкой и что эта проверка передаёт остальным проверкам группы.

## 6.1. Предмет проверки

Проверяется, куда попадёт почта, отправленная на адрес в этом домене, и пригодно ли найденное к доставке.

Проверка не отправляет писем и не обращается к найденному серверу: соединение с ним — предмет [§7](07-starttls.md#7-starttls).

## 6.2. Как находится сервер

Порядок установлен RFC 5321 и повторён в RFC 7505: отправитель запрашивает `MX` домена, а не найдя их, обращается к адресным записям самого домена.

| Что опубликовано | Принимающий сервер |
|---|---|
| одна или несколько записей `MX` | узлы из этих записей, в порядке предпочтения |
| `MX` нет, есть адресные записи | сам домен, неявно |
| `MX` вида «почту не принимаю» | сервера нет намеренно |
| нет ни `MX`, ни адресных записей | сервера нет |

Null MX — единственная запись `MX` с предпочтением `0` и обменником `.` (корневое имя), определённая в [RFC 7505](https://www.rfc-editor.org/rfc/rfc7505.html#section-3). Она объявляет, что домен не принимает почту. Пустая строка вместо имени не является её текстовым представлением.

## 6.3. Результаты

| Состояние | Статус | Серьёзность | Что передаётся дальше |
|---|---|---|---|
| записи `MX` есть и пригодны | `PASS` | — | узлы для [§7](07-starttls.md#7-starttls) и [§8](08-ptr.md#8-ptr) |
| запись «почту не принимаю» | `PASS` | — | `blockedBy = null_mx` |
| `MX` нет, доставка пойдёт по адресным записям | `FAIL` | `warning` | сам домен как узел |
| нет ни `MX`, ни адресных записей | `FAIL` | `warning` | `blockedBy = mx_missing` |
| записи `MX` есть, но ни один узел не пригоден | `FAIL` | `critical` | `blockedBy = mx_missing` |

Корректная запись Null MX получает `PASS` за явное объявление о неприёме почты.

При отсутствии `MX` адресные записи определяют неявный маршрут доставки. Уровень `warning` рекомендует явно указать почтовые серверы или объявить неприём почты. Он не означает, что доставка была проверена.

## 6.4. Пригодность узла

| Что найдено у узла | Статус | Серьёзность |
|---|---|---|
| адресные записи есть | узел пригоден | — |
| узел — псевдоним `CNAME` | `FAIL` | `warning` |
| адресных записей нет | узел непригоден | — |
| вместо имени записан адрес | `FAIL` | `critical` |

Узел `MX` должен иметь адресные записи и не должен быть псевдонимом — RFC 2181. Уровни `warning` для псевдонима и `critical` для адреса вместо имени задаются политикой оценки продукта; поведение конкретных отправителей не проверяется.

Если все узлы непригодны, результат получает `critical`. При частичной непригодности результат — `FAIL` с серьёзностью `warning` и перечнем затронутых узлов. Пригодность DNS-маршрута не подтверждает фактическую доставку.

## 6.5. Технический сбой

| Причина | `reasonCode` |
|---|---|
| запрос `MX` не завершился | `mx_lookup_failed` |
| адреса узлов не разрешились по техническим причинам | `mx_host_resolution_failed` |

Незавершённый запрос даёт `UNKNOWN`, а не вывод об отсутствии записей. Правила `reasonCode` и `blockedBy` — [1.0 §7](../prd/07-shared-status-dependency-category-scan-semantics.md#7-статусы-зависимости-и-результаты-сканирования).

## 6.6. Чего проверка не утверждает

- Что сервер принимает почту: DNS-записи этого не подтверждают; проба [§7](07-starttls.md#7-starttls) проверяет только установление шифрованного соединения.
- Что почта дойдёт до почтового ящика: маршрут за принимающим сервером публичным данным не виден.
- Что порядок предпочтения выбран правильно: предпочтение выражает намерение владельца.

## 6.7. Критерии приёмки

- **AC-6.1** Принимающий сервер определяется в порядке RFC 5321: записи `MX`, затем адресные записи домена.
- **AC-6.2** Единственная запись `MX` с предпочтением `0` и обменником `.` распознаётся как Null MX и даёт `PASS`.
- **AC-6.3** Отсутствие `MX` при наличии адресных записей даёт `FAIL` с серьёзностью `warning` и передаёт сам домен как узел.
- **AC-6.4** Отсутствие `MX` и адресных записей даёт `FAIL` с серьёзностью `warning` и `blockedBy = mx_missing` для зависимых проверок.
- **AC-6.5** Непригодность всех узлов даёт `FAIL` с серьёзностью `critical`.
- **AC-6.6** Узел-псевдоним даёт `FAIL` с серьёзностью `warning`; адрес вместо имени даёт `FAIL` с серьёзностью `critical`.
- **AC-6.7** Незавершённый запрос даёт `UNKNOWN` с `reasonCode`, а не вывод об отсутствии записей.
- **AC-6.8** Проверка не устанавливает соединения с найденными узлами.
