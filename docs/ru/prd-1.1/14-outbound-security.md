# 14. Безопасность исходящих соединений

<!-- nav:start -->
[Концепция](../01-concept.md) · [Оглавление PRD 1.1](../03-prd-1.1.md) · [English](../../en/prd-1.1/14-outbound-security.md)
<!-- nav:end -->

§14 определяет правила, по которым допускается соединение с почтовым узлом. Ответственный раздел для проверки адресов — 1.0 §15; его последовательность, классификация адресов и правило блокировки здесь не меняются, а распространяются на новый вид соединения.

## 14.1. Почему нужен отдельный раздел

До этого релиза продукт устанавливал исходящие соединения двух видов: запросы к резолверам и запросы по HTTPS к реестру. Оба идут по фиксированным адресам, заданным конфигурацией.

Проба шифрования устроена иначе: она соединяется с узлом, имя которого назвал проверяемый домен. Это первый случай, когда чужая запись влияет на то, куда мы подключаемся, — и именно та конструкция, от которой защищает 1.0 §15.

## 14.2. Последовательность

Порядок 1.0 §15 применяется без изъятий:

```text
MailHostTarget
→ DNS A/AAAA
→ full candidate set
→ Security Validation
→ ALLOW | BLOCK | INDETERMINATE
→ selected validated endpoint
→ pinned connection
```

Полный набор адресов узла проверяется без предварительного усечения. Если запрещён хотя бы один адрес, блокируется весь узел; исключить запрещённый адрес и соединиться с остальными нельзя — 1.0 §15.

Соединение идёт к закреплённому адресу. Имя узла не разрешается повторно библиотекой соединения.

## 14.3. Что ограничено жёстко

| Ограничение | Значение |
|---|---|
| порт | только `25` |
| источник имён узлов | только §6 |
| команды сеанса | только приветствие, запрос расширений, переход на шифрование, завершение |
| число узлов за проверку | не более четырёх — §7 |

Порт не берётся ни из ввода читателя, ни из записей домена. Записи `MX` содержат имя, но не порт, и добавлять его туда неоткуда — эта строка существует, чтобы будущая реализация не «улучшила» проверку произвольным портом.

Команды отправителя, получателя и передачи данных не выдаются никогда. Проба не отправляет писем и потому не может быть использована ни для рассылки, ни для проверки существования адресов.

## 14.4. Что это исключает

| Попытка | Почему не работает |
|---|---|
| заставить сервис соединиться с внутренним адресом | адрес узла проходит проверку 1.0 §15 наравне с любым другим |
| подменить адрес между проверкой и соединением | соединение идёт к закреплённому адресу |
| использовать сервис для сканирования портов | порт фиксирован |
| использовать сервис как усилитель нагрузки | узлы берутся только из записей проверяемого домена, их число ограничено |
| отправить письмо чужими руками | команды передачи данных не выдаются |

## 14.5. Собственная инфраструктура

Запрет доступа к собственной инфраструктуре — 1.0 §15 — распространяется на почтовые узлы без изменений.

Блокировка по этой причине даёт `UNKNOWN` с объяснением, что это ограничение сервиса, и не уменьшает оценку домена. Проверка, которая называет недостатком домена нашу собственную сетевую политику, ошибается в обе стороны сразу: она и обвиняет невиновного, и скрывает нашу проблему.

## 14.6. Бюджет времени

Проба подчиняется общему бюджету сканирования 1.0 §22. Отдельного бюджета категория не вводит.

Из этого следует правило §7: узлы сверх предела перечисляются как неопрошенные, а не ожидают освобождения времени. Результат, полученный частично, сообщается как частичный.

## 14.7. Критерии приёмки

- **AC-14.1** Адреса почтового узла проходят проверку безопасности 1.0 §15 в полном наборе, без усечения.
- **AC-14.2** Запрещённый адрес блокирует узел целиком.
- **AC-14.3** Соединение устанавливается к закреплённому адресу; повторное разрешение имени не допускается.
- **AC-14.4** Порт соединения равен `25` и не может быть задан вводом или записями домена.
- **AC-14.5** Имена узлов берутся только из результата §6.
- **AC-14.6** В сеансе не выдаются команды отправителя, получателя и передачи данных.
- **AC-14.7** Блокировка по запрету собственной инфраструктуры даёт `UNKNOWN` и не уменьшает оценку домена.
- **AC-14.8** Категория не вводит собственного бюджета времени.
