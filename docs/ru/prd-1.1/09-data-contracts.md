# 9. Контракты данных и уровни раскрытия

<!-- nav:start -->
[Концепция](../01-concept.md) · [Оглавление PRD 1.1](../03-prd-1.1.md) · [English](../../en/prd-1.1/09-data-contracts.md)
<!-- nav:end -->

[§9](09-data-contracts.md#9-контракты-данных-и-уровни-раскрытия) определяет структуры, которыми категория `email` пользуется в общих контрактах 1.0, и то, какие из её данных попадают в какое представление. Ответственный раздел для самих контрактов — [1.0 §6](../prd/06-common-data-contracts-exposure.md#6-общие-контракты-данных-и-уровни-доступа); здесь определяются только варианты для этой категории.

## 9.1. Категория

Перечисление категорий пополняется одним значением:

```text
category: dns | registry | tls | email
```

Порядок перечисления в интерфейсе определяется [1.0 §23](../prd/23-frontend-ux-result-presentation.md#23-пользовательский-интерфейс-и-представление-результатов) и в этом разделе не задаётся.

## 9.2. Объект проверки

```text
EmailCheckTarget =
  EmailPolicyTarget |
  MailHostTarget

EmailPolicyTarget {
  kind: EMAIL_POLICY
  policy: SPF | DMARC | DKIM
  queriedName
}

MailHostTarget {
  kind: MAIL_HOST
  hostname
  preference?
  ipFamily?: IPV4 | IPV6
  implicit?
}
```

`queriedName` — имя, у которого политика была запрошена. Для DMARC это имя может принадлежать вышестоящему домену, а для DKIM — содержать селектор, поэтому оно часть объекта проверки, а не подробностей: без него результат нельзя прочитать.

`implicit` отмечает узел, полученный из адресных записей домена при отсутствии `MX` — [§6](06-mx.md#6-mx).

## 9.3. Происхождение результата

```text
EmailCheckSource =
  DnsRecordSource |
  SmtpProbeSource

DnsRecordSource {
  kind: DNS_RECORD
  traversedNames?
  voidLookups?
}

SmtpProbeSource {
  kind: SMTP_PROBE
  hostsProbed
  hostsSkipped
}
```

`hostsProbed` и `hostsSkipped` отдельно отражают опрошенные и пропущенные узлы. Наличие пропущенных узлов означает неполное покрытие. Равенство или неравенство этих количеств само по себе полноту не определяет — [§7](07-starttls.md#7-starttls).

## 9.4. Уровни раскрытия

| Данные | Представление |
|---|---|
| статус, серьёзность, сообщение | Public |
| политика и её ключевые значения | Public |
| имя, у которого найдена политика | Public |
| узлы `MX` и порядок предпочтения | Public |
| адреса узлов | Technical |
| исходный текст записей | Technical |
| опрошенные имена селекторов | Technical |
| домены получателей отчётов DMARC | Public |
| полные адреса получателей отчётов DMARC | Technical |

Домен получателя позволяет определить, направляются ли отчёты стороннему сервису. Полный адрес доступен в техническом представлении по явному запросу. Его отсутствие в публичной сводке сокращает повторное распространение адресов, уже опубликованных в DNS.

Gated-данных в этой категории нет.

## 9.5. Машинные значения

К перечню [1.0 §6](../prd/06-common-data-contracts-exposure.md#6-общие-контракты-данных-и-уровни-доступа) добавляются, как нелокализуемые:

- имена и значения тегов политик;
- имена селекторов;
- имена узлов и их порядок предпочтения.

## 9.6. Критерии приёмки

- **AC-9.1** Перечисление категорий пополняется единственным значением `email`.
- **AC-9.2** `EmailCheckTarget` и `EmailCheckSource` имеют структуру, определённую этим разделом, и не являются произвольными полями.
- **AC-9.3** Имя, у которого запрошена политика, входит в объект проверки.
- **AC-9.4** Узел, полученный из адресных записей домена, отмечается признаком `implicit`.
- **AC-9.5** Число опрошенных и число неопрошенных узлов различаются в данных результата.
- **AC-9.6** Адреса узлов и исходный текст записей не входят в представление Public.
- **AC-9.7** Полные адреса получателей отчётов DMARC не входят в представление Public; их домены входят.
- **AC-9.8** Категория не определяет Gated-данных.
