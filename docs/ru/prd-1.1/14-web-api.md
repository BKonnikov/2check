# 14. Веб-API и режимы сканирования

<!-- nav:start -->
[Концепция](../01-concept.md) · [Оглавление PRD 1.1](../03-prd-1.1.md) · [English](../../en/prd-1.1/14-web-api.md)

[§14](14-web-api.md#14-веб-api-и-режимы-сканирования) определяет, как категория `email` входит в контракт внутреннего веб-API и в режимы сканирования. Ответственные разделы — [1.0 §17](../prd/17-internal-web-api-contract.md#17-контракт-внутреннего-веб-api) и [1.0 §3](../prd/03-user-scenarios-scan-modes.md#3-пользовательские-сценарии-и-режимы-сканирования); конечные точки, модель приёма и правила опроса здесь не меняются.

## 14.1. Выбор категорий

Перечисление в запросе пополняется одним значением:

```text
selectedCategories?: (dns | registry | tls | email)[]
```

Правило [1.0 §17](../prd/17-internal-web-api-contract.md#17-контракт-внутреннего-веб-api) сохраняется дословно: `PARTIAL` принимает непустое собственное подмножество категорий, а выбор всех создаёт `FULL`. Собственным подмножеством теперь считается подмножество из четырёх категорий, а не из трёх.

После добавления `email` запрос `PARTIAL` с категориями `dns`, `registry` и `tls` становится допустимым: он выбирает собственное подмножество доступных категорий.

## 14.2. Селектор

Запрос на создание сканирования пополняется необязательным полем:

```text
CreateScanRequest {
  input
  mode: FULL | PARTIAL
  selectedCategories?
  cacheMode?
  dkimSelector?
}
```

Поле принимается только при наличии `email` в объёме проверки. В остальных случаях запрос отклоняется с HTTP `422` и указанием некорректного поля. Переданное значение не игнорируется.

Значение проверяется как метка имени DNS. Селектор, не проходящий эту проверку, отклоняется до выполнения запросов, а не превращается в неудачный поиск.

Селектор относится к запросу, а не к домену: правила кэша — [§12](12-cache.md#12-кэширование-и-актуальность-данных).

## 14.3. Оценка и вердикт

Общая оценка и общий вердикт доступны только для `FULL + FINAL` — [1.0 §3](../prd/03-user-scenarios-scan-modes.md#3-пользовательские-сценарии-и-режимы-сканирования). Добавление категории этого не меняет: `PARTIAL` с одной только категорией `email` показывает её результаты без общей оценки домена.

## 14.4. Ошибки

Собственных кодов ошибок категория не вводит. Отказ по селектору использует общий контракт `WebApiError` [1.0 §17](../prd/17-internal-web-api-contract.md#17-контракт-внутреннего-веб-api) с указанием поля.

## 14.5. Критерии приёмки

- **AC-14.1** Перечисление выбираемых категорий пополняется значением `email`.
- **AC-14.2** Выбор всех четырёх категорий создаёт `FULL`; `PARTIAL` со всеми четырьмя отклоняется с HTTP `422`.
- **AC-14.3** `PARTIAL` с категориями `dns`, `registry` и `tls` допустим.
- **AC-14.4** Поле `dkimSelector` принимается только при наличии категории `email` в объёме проверки.
- **AC-14.5** Запрос с `dkimSelector` без категории `email` отклоняется с HTTP `422` и не выполняется.
- **AC-14.6** Значение `dkimSelector` проверяется как метка имени DNS до выполнения запросов.
- **AC-14.7** `PARTIAL` с категорией `email` не получает общей оценки и общего вердикта.
- **AC-14.8** Категория не вводит собственных кодов ошибок веб-API.
