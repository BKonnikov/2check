# 15. Веб-API и режимы сканирования

<!-- nav:start -->
[Концепция](../01-concept.md) · [Оглавление PRD 1.1](../03-prd-1.1.md) · [English](../../en/prd-1.1/15-web-api.md)
<!-- nav:end -->

§15 определяет, как категория `email` входит в контракт внутреннего веб-API и в режимы сканирования. Ответственные разделы — 1.0 §17 и 1.0 §3; конечные точки, модель приёма и правила опроса здесь не меняются.

## 15.1. Выбор категорий

Перечисление в запросе пополняется одним значением:

```text
selectedCategories?: (dns | registry | tls | email)[]
```

Правило 1.0 §17 сохраняется дословно: `PARTIAL` принимает непустое собственное подмножество категорий, а выбор всех создаёт `FULL`. Собственным подмножеством теперь считается подмножество из четырёх категорий, а не из трёх.

Из этого следует изменение, которое легко пропустить: запрос `PARTIAL` с категориями `dns`, `registry` и `tls` до этого релиза отклонялся как полный, а теперь допустим. Правило не переписано — изменился набор, к которому оно применяется.

## 15.2. Селектор

Запрос на создание сканирования пополняется необязательным полем:

```text
CreateScanRequest {
  input
  mode: FULL | PARTIAL
  selectedCategories?
  cacheMode?
  dkimSelector?
}
```

Поле принимается только тогда, когда категория `email` входит в объём проверки. Запрос с селектором без этой категории отклоняется как некорректный: HTTP `422`. Молча игнорировать переданное значение нельзя — клиент, приславший селектор, вправе знать, что его не использовали.

Значение проверяется как метка имени DNS. Селектор, не проходящий эту проверку, отклоняется до выполнения запросов, а не превращается в неудачный поиск.

Селектор относится к запросу, а не к домену: правила кэша — §13.

## 15.3. Оценка и вердикт

Общая оценка и общий вердикт доступны только для `FULL + FINAL` — 1.0 §3. Добавление категории этого не меняет: `PARTIAL` с одной только категорией `email` показывает её результаты без общей оценки домена.

## 15.4. Ошибки

Собственных кодов ошибок категория не вводит. Отказ по селектору использует общий контракт `WebApiError` 1.0 §17 с указанием поля.

## 15.5. Критерии приёмки

- **AC-15.1** Перечисление выбираемых категорий пополняется значением `email`.
- **AC-15.2** Выбор всех четырёх категорий создаёт `FULL`; `PARTIAL` со всеми четырьмя отклоняется с HTTP `422`.
- **AC-15.3** `PARTIAL` с категориями `dns`, `registry` и `tls` допустим.
- **AC-15.4** Поле `dkimSelector` принимается только при наличии категории `email` в объёме проверки.
- **AC-15.5** Запрос с `dkimSelector` без категории `email` отклоняется с HTTP `422` и не выполняется.
- **AC-15.6** Значение `dkimSelector` проверяется как метка имени DNS до выполнения запросов.
- **AC-15.7** `PARTIAL` с категорией `email` не получает общей оценки и общего вердикта.
- **AC-15.8** Категория не вводит собственных кодов ошибок веб-API.
